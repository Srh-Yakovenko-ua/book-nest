# Release to prod, 2026-11-26

Promotes `dev` onto `prod` (`f4197b1e`, released 2026-11-17). The exact promoted SHA is recorded on the promote PR.

## Delivery mechanics

Merging the promote PR pushes `prod`, which triggers `.github/workflows/deploy.yml`: build `:prod` images, push to GHCR, SSH to the box, `deploy.sh prod` (`compose pull`, `up -d`, health check, roll the image back if unhealthy). The api container runs `prisma migrate deploy` on boot, but this release carries no migration, so that step finds nothing to apply. The changelog seed runs on the same boot and adds the new What's New entries.

## Scope

`prod`'s tree is byte-identical to dev commit `0f4d09b1` ("docs(releases): notes for the 2026-11-17 prod release"), so everything new is `0f4d09b1..dev`. The counts below cover `0f4d09b1..242c3b6a`, the last merge before the two release commits (changelog entries and these notes):

The release has four subjects: a home page rebuilt as a daily reading dashboard, reading goals with correct event counts, a late-forecast risk and a reworked goal page, a relationship map that stays readable on large books (whole genealogy in the family tree, a network built around groups, a redesigned view around a character), and a calendar, statistics and settings pass that fits each screen into one view.

## Pending migrations

None. `apps/api/prisma/` is unchanged between `prod` and `dev`, so there is no schema change, no strip-trap risk and no data-dependent migration to rehearse.

## Pre-flight (prod copy)

No migration needed a rehearsal, but one new script did need a measurement. #399 adds `pnpm --filter @app/api backfill:reading-goal-ordinals`, which rewrites old `book_counted` events with the new counting rule. It is manual, a dry run unless given `--apply`, and nothing runs it on deploy. Its PR asks for a dry run on a copy first.

`pnpm db:copy:prod` dumped the live prod database read-only (3.1 MB) and loaded it into a throwaway local container on port 5434. The load printed only the usual `booknest_ro` grant errors. On that copy:

- 3 users, 230 books, 135 changelog entries and 117 finished migrations, the last applied on 2026-11-17, which matches the previous release
- `reading_goals` and `reading_goal_activities` hold 0 rows, and the dump itself has 0 rows under `COPY public.reading_goals`
- `character_graph_layouts` holds 0 rows

So the backfill has nothing to rewrite on prod and does not need to run there. The copy container was removed after counting.

## Headline features

### Home

- **Daily reading dashboard.** The home page greets the reader by the time of day and shows the books in progress, what to read next and what needs attention. New read-only routes under `/api/home`: `reading`, `reading/books`, `next-read` and `attention`.

### Reading goals

- **Event counts.** Two books finished on the same day no longer both read "counted 1 of 5". Each `book_counted` event now stores how many books were counted right after it, in the order the events were recorded.
- **Late forecast.** An active goal whose confident forecast ends after the deadline gets the new `projected_late` risk reason, so it no longer reads "on track" and "finishes 15 days late" at once.
- **Goal page.** One header and progress hero above Overview, Books and History tabs, a checkpoint timeline, one clear next step, and pace advice in whole days.
- **Count before saving.** The create form tells you how many of a list's books will count, through the new `GET /api/lists/:listId/goal/preview`.

### Relationship map

- **Whole genealogy.** The family tree gains a second mode that shows every generation of a book's families on one canvas, served by the new read-only `GET /api/books/:bookId/character-graph/family-tree` with the same spoiler masking and caps as the focused tree.
- **Network.** The whole network view opens on an overview of groups and lets the reader focus on one group, with search, a side panel and a mini map.
- **Around a character.** Round portraits, lines coloured by category, a searchable list of pairs under the graph and a details panel that sits beside the graph on wide screens.

### Calendar, statistics and settings

- **Reading calendar.** A poster grid of the books read each day and one quarter of reading intensity beside it.
- **Statistics.** The Progress tab becomes a two-row dashboard and the Tastes tab is compacted.
- **Settings.** Reminders and date settings in two cards with autosave per field, a time zone search by city with the current UTC offset, and a test notification that no longer reports an error on its empty 202 answer.

### Dependencies

- **next 16.4.6** closes 12 advisories. The image optimizer now accepts only `/illustrations/**`. Every cover `next/image` already passes `unoptimized`, and on dev `/_next/image` returns 200 for `/illustrations/sidebar.png` and 400 for `/api/health`.
- **nodemailer 10.5** closes the two high advisories in the address parser. On dev it has already sent a notification digest through the server's Mailpit with no mail error in the log. A send through the real prod SMTP provider is first seen after this deploy.
- **prisma 7.10.1**, **nestjs-zod 5.6** (restores `pnpm gen:api`), dev tooling advisory overrides, shadcn moved to web dev dependencies.

## Runbook

1. Changelog entries and these notes go to `dev` first, and the dev deploy boots the seed as a canary.
2. Commit-tree promotion: tree of `dev`, parent `origin/prod`, pushed as `promote-prod`, PR into `prod`.
3. The prod PR runs the CI gate (`static`, `test-api` four-way shard, `test-web` three-way shard, `build` plus API smoke against a `migrate deploy`'d empty database, then the `CI gate` fan-in).
4. Squash-merge, `prod` push, deploy workflow.
5. Verify `https://book-nest.net/api/health` returns `"status":"ok"` with a fresh uptime, that a new route answers 401 instead of 404, that the What's New feed carries 140 entries, and that the prod api log shows no mail error.

### Rollback

`deploy.sh` rolls the image back automatically if the container never turns healthy. With no migration in this release, the previous image runs over the exact schema it was built for.

The only new stored value is the layout mode `genealogy` in `character_graph_layouts.mode`, a plain text column. The previous image reads and deletes layouts only by their full key including the mode and never lists them, so a `genealogy` row stays invisible to it. Prod has no layout rows today. New What's New entries stay in the table after a rollback and show as usual, since the previous image reads the same columns.

Prod has no automated backups. The `pg_dump` taken for the pre-flight, `/tmp/booknest_prod_dump.sql` on the release machine, is kept until the deploy is verified.
