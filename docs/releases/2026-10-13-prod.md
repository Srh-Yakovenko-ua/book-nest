# Release to prod, 2026-10-13

Promotes `dev` onto `prod` (`9e4e299d`, released 2026-09-27). The exact promoted SHA is recorded on the promote PR.

## Delivery mechanics

Merging the promote PR pushes `prod`, which triggers `.github/workflows/deploy.yml`: build `:prod` images, push to GHCR, SSH to the box, `deploy.sh prod` (`compose pull`, `up -d`, health check, roll the image back if unhealthy). The api container runs `prisma migrate deploy` against the live prod database on boot via `apps/api/docker-entrypoint.sh`, so the four migrations below apply automatically on the first boot of the new image.

## Scope

`prod`'s tree is byte-identical to dev commit `f1897aa0` ("docs(releases): notes for the 2026-09-27 prod release"), so everything new is `f1897aa0..dev`:

- 72 commits (42 non-merge), 29 merged PRs: #232 to #251, #253 and #256 to #263. The open dependabot bumps (#193, #206 to #215, #252, #254, #255) stay behind
- 471 files, +45353 / -4068: 322 web, 119 api, 6 shared, 23 docs, plus `CLAUDE.md`
- 93 of the 322 web files are the regenerated Orval client, so the hand-written web change is 229 files
- The uk locale catalogue grew from 6357 keys to 6556, and gained one new top-level namespace, `species`

The release has three subjects: publishers that stop duplicating, characters with a species catalog and a reworked edit page, and the book timeline's chapter suggestions. Around them sit a regrouped sidebar that finally links to Characters and a reading queue dialog that no longer drops typing on Cancel.

## Pre-flight (prod copy)

`pnpm db:copy:prod` dumped the live prod database read-only and loaded it into a throwaway local container on port 5434. `migrate deploy` then ran against that copy with `APP_ENV=prodcopy`, so `prisma.config.ts` loaded no env file and could not fall back to the local dev database. Prisma reported `injected env (0) from .env.prodcopy` and its datasource as `localhost:5434`.

- The live prod database was at 106 applied migrations, exactly the 106 in `prod`'s own tree
- `migrate status` listed the four migrations above as pending, and nothing else
- `migrate deploy` applied all four, exit 0
- `migrate status` afterwards reports "Database schema is up to date!" at 110
- Sixteen of sixteen hand-written indexes present afterwards, and `books_publisher_id_fkey` reads `ON DELETE RESTRICT`
- Row counts across all 62 pre-existing tables were identical before and after. The only differences are the two new tables, `species` at 114 rows and `species_names` at 228, and four new `_prisma_migrations` rows
- Before the run prod held 230 books, 1409 publishers, 1 character and 1 book appearance, with no species text and no unreliable narrator, so both backfills had nothing to move
- The copy container was removed afterwards, since it holds real user data

## Headline features

### Publishers

- **Merge a duplicate.** One custom publisher can be merged into another. Every book moves, trashed ones included, and the emptied duplicate is removed. A catalog publisher chosen as the target is never changed. The delete dialog of a publisher in use offers the merge instead of a dead end.
- **Recognised by every name.** A typed name is matched against all of a publisher's names and a transliteration of the input, so "Віват" finds "Видавництво Vivat". An exact match is used instead of creating a copy, near matches are offered and say which name matched, and a typed but unselected publisher is no longer silently dropped when the book form is saved.
- **One page per publisher.** The Overview and Books tabs became one books page with a sticky sidebar for what is being read, the series, the wishlist and the latest addition. Old `?tab=` links still land on it.

### Characters

- **Species catalog.** Species is a picker over 114 shared species found by their Ukrainian or English name, plus private species per user, with a manager to search, rename, merge and delete them. The picker scrolls through the whole catalog. This is migrations 2 and 3.
- **Edit page rework.** The edit page follows the edit book layout. Roles are chips (up to five), status and gender take a custom value in the same field, other names are chips with an inline editor, chapters and the user's own roles and statuses are suggested, and one image panel manages both the main avatar and the book portrait.
- **Unreliable narrator.** Unreliability is now its own flag with its own spoiler mark, so a first-person unreliable narrator can be recorded. This is migration 4.
- **Spoiler data-loss fix.** Saving a character used to delete the roles and other names hidden from the reader as spoilers, because the write path replaced both collections with what the client had been shown. Both now go through the same reveal contract as every other masked field.
- **One query contract.** The roster, the suggestion list and the add-character picker read characters the same way, so a character past the reader's position no longer leaks through suggestions. The roster scrolls endlessly.

### Timeline, navigation and the reading queue

- **Chapter suggestions.** The event form's chapter field suggests the chapters the book already uses in notes, quotes and events, so one chapter stops being stored four ways. "Save and add another" keeps the place in the book.
- **Sidebar sections.** Navigation is grouped into sections, Characters is finally in it, and a collapsed section opens a flyout instead of jumping to its first child.
- **Reading queue.** Cancel in the volume dialog asks before discarding typed data, like the other three ways out already did.

## Runbook

1. Pre-flight against a prod copy (above), green.
2. Commit-tree promotion: tree of `dev`, parent `origin/prod`, pushed as `promote-prod`, PR into `prod`.
3. The prod PR runs the CI gate (`static`, `test-api` four-way shard, `test-web`, `build` plus API smoke against a `migrate deploy`'d empty database, then the `CI gate` fan-in).
4. Squash-merge, `prod` push, deploy workflow, migrations auto-apply on api boot.
5. Verify `https://book-nest.net/api/health` returns `"status":"ok"` with a fresh uptime, that `/api/species/browse` answers 401 rather than 404, and that the What's New feed carries 114 entries.

### Rollback

`deploy.sh` rolls the image back automatically if the container never turns healthy. It does not roll migrations back. Under the previous image all four are tolerable. It never reads the new tables or columns, and the two new booleans have defaults its inserts satisfy. It still writes species as free text, so a character edited during a rollback would not be linked to the catalog until the new image runs again. Deleting a custom publisher whose books are all trashed would fail on the `RESTRICT` key with a 500 instead of quietly unlinking them, which is the safer of the two failures.

Prod has no automated backups. The `pg_dump` taken for this pre-flight, `/tmp/booknest_prod_dump.sql` on the release machine, is the only restore point and is kept until the deploy is verified.
