# Release to prod — 2026-08-05

Promotes `dev` (`0a69f9d`) onto `prod` (`92bc6b5`, released 2026-07-24).

## Delivery mechanics

Merging the promote PR pushes `prod`, which triggers `.github/workflows/deploy.yml`: build `:prod` images → push to GHCR → SSH to the box → `deploy.sh prod` (`compose pull` → `up -d` → health-check → roll back the image if unhealthy). The api container runs `prisma migrate deploy` against the live prod database on boot via `apps/api/docker-entrypoint.sh`, so the eleven migrations below apply automatically on the first boot of the new image.

## Runbook

1. Pre-flight against a prod copy (above) — green.
2. Commit-tree promotion: tree of `origin/dev`, parent `origin/prod`, pushed as `promote-prod`, PR into `prod`.
3. Prod PR runs the `full` CI gate (build, `migrate deploy` on empty Postgres, tests, API smoke).
4. Squash-merge → `prod` push → deploy workflow → migrations auto-apply on api boot.
5. Verify `https://book-nest.net/api/health` returns `"status":"ok"`.

### Rollback

`deploy.sh` rolls the **image** back automatically if the container never turns healthy. It does not roll migrations back — every migration here is additive (new nullable columns, new tables, new indexes), so the previous image keeps running against the migrated schema without a schema conflict.
