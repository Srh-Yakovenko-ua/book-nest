# Release to prod, 2026-10-19

Promotes `dev` onto `prod` (`581b87ff`, released 2026-10-13). The exact promoted SHA is recorded on the promote PR.

## Delivery mechanics

Merging the promote PR pushes `prod`, which triggers `.github/workflows/deploy.yml`: build `:prod` images, push to GHCR, SSH to the box, `deploy.sh prod` (`compose pull`, `up -d`, health check, roll the image back if unhealthy). The api container runs `prisma migrate deploy` against the live prod database on boot via `apps/api/docker-entrypoint.sh`, so the three migrations below apply automatically on the first boot of the new image.

## Pre-flight (prod copy)

`pnpm db:copy:prod` dumped the live prod database read-only and loaded it into a throwaway local container on port 5434. `migrate deploy` then ran against that copy with `APP_ENV=prodcopy`, so `prisma.config.ts` loaded no env file and could not fall back to the local dev database. Prisma reported its datasource as `localhost:5434`.

- `migrate status` found 113 migrations and listed exactly the three above as pending, so prod sat at 110
- `migrate deploy` applied all three, exit 0
- `migrate status` afterwards reports "Database schema is up to date!"
- `characters` 4, `book_characters` 4 and `notes` 49 rows before and after. `character_facts` exists and is empty, `notes.title` is null everywhere
- The copy container was removed afterwards, since it holds real user data

## Headline features

### Characters

- **Relationships.** Characters can be linked by typed relationships with a status, an intensity and a start and end point in a book. A character page has a Relationships tab, a book's Characters tab switches between List, Relationships and an interactive Graph with shortest-path search, and a series page gets a Characters tab shown as of a chosen book.
- **Spoiler model.** A character is never hidden from a book any more, neither by its first appearance nor by a flag. Spoiler fields are masked on the server and revealed one by one, forms included. This is migration 1.
- **Facts.** A character can carry per-book facts with a title, text, chapter and page. This is migration 3.
- **Roster.** Compact roster cards and filters by importance, Favorites and POV, kept in the URL.
- **Details and edit pages.** The details page is rebuilt around its book or global context, and the edit form is regrouped, with a reworked editor for other names and for book-specific name and species.

### Notes, quotes and timeline

- **Book tabs.** Notes and quotes each get their own tab on the book page with search, quick filters, sorting and endless scroll.
- **Note titles.** Book and series notes take an optional title. This is migration 2.
- **Suggestions.** The Chapter field of notes and quotes suggests the book's chapters, and the timeline event form suggests saved locations.

### Statistics and goals

- **Statistics tabs.** Overview, Activity, Tastes and Progress under one period selector. Clicking a chart bar lists exactly the reads or pages behind it. The calendar gains month counters and covers per day, and "today" follows the profile time zone.
- **Goals catalog.** `/goals` lists every goal with status filters and sorting and creates a goal for a chosen list. A goal's page has Overview, Books and Activity tabs, and finishing a book updates its goal without a reload.

## Runbook

1. Pre-flight against a prod copy (above), green.
2. Commit-tree promotion: tree of `dev`, parent `origin/prod`, pushed as `promote-prod`, PR into `prod`.
3. The prod PR runs the CI gate (`static`, `test-api` four-way shard, `test-web`, `build` plus API smoke against a `migrate deploy`'d empty database, then the `CI gate` fan-in).
4. Fresh read-only `pg_dump` of prod right before the merge, kept as the restore point.
5. Squash-merge, `prod` push, deploy workflow, migrations auto-apply on api boot.
6. Verify `https://book-nest.net/api/health` returns `"status":"ok"` with a fresh uptime, and that the What's New feed carries 125 entries.

### Rollback

`deploy.sh` rolls the image back automatically if the container never turns healthy. It does not roll migrations back, and this time that matters. Migrations 2 and 3 are harmless under the previous image, which never reads `notes.title` or `character_facts`. Migration 1 is not: the previous image's Prisma client names both dropped columns in every query that reads or returns a whole character or book appearance row, so after a rollback most character endpoints would fail with a 500 until the new image is back. The repair is to restore the columns, which brings them back exactly as they were on prod since every row held `false`:

```sql
ALTER TABLE "book_characters" ADD COLUMN "hide_presence_as_spoiler" BOOLEAN NOT NULL DEFAULT false;
ALTER TABLE "characters" ADD COLUMN "hide_profile_as_spoiler" BOOLEAN NOT NULL DEFAULT false;
```

Prod has no automated backups. The `pg_dump` taken in step 4, `/tmp/booknest_prod_dump.sql` on the release machine, is the only restore point and is kept until the deploy is verified.
