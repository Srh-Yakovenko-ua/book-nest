# Повний обсяг реалізації

Усі пункти нижче є частиною одного повного функціоналу. Їх не слід відкладати як «після MVP».

## Виявлення

- попередньої книги немає в черзі;
- попередня книга є в черзі, але стоїть нижче;
- відсутні кілька попередніх книг;
- попередня книга на паузі;
- активне читання випереджає канонічний порядок;
- попередня книга має `NONE`;
- попередня книга має `WANT_TO_BUY`;
- попередня книга має `IN_TRANSIT`;
- попередня книга має `LENT_TO`;
- доступна `BORROWED_FROM` книга відсутня в черзі;
- кілька книг серії переплутані;
- повністю зворотний порядок;
- коректне ігнорування `finished` і доменно закритого `dnf`;
- підтримка gaps, фактичного типу позицій, `null` та duplicate positions без хибних warnings.

## Відображення

- одна картка на серію;
- максимум три issue items у sidebar;
- загальна кількість issues;
- severity;
- зрозуміле пояснення;
- current order;
- recommended order;
- основна та додаткові дозволені дії;
- сторінка, модалка або наявний маршрут «Переглянути всі»;
- loading, error, empty і success states.

## Виправлення

- preview перед кожною mutation, що змінює більше одного queue item;
- вставка першої попередньої книги перед проблемною;
- вставка всіх відсутніх попередніх книг;
- перестановка лише книг серії у зайнятих ними слотах;
- відсутність duplicate queue items;
- перевірка queue limit;
- атомарна транзакція;
- optimistic concurrency;
- rollback у разі помилки;
- invalidation/refetch після успіху.

## Користувацькі рішення

- «Залишити як є» для конкретного fingerprint;
- повторна поява issue після зміни його fingerprint;
- «Не перевіряти цю серію»;
- повторне ввімкнення перевірки в налаштуваннях серії;
- перехід до книги, покупки, замовлення або позики без прихованих змін даних.

## Якість

- read-only аудит перед змінами;
- відсутність дубльованого алгоритму;
- відсутність N+1;
- user isolation;
- i18n;
- keyboard accessibility;
- focus management;
- unit, integration/e2e та frontend tests;
- перевірка старих queue і series flows на регресії.
