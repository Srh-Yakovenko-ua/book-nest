# Алгоритм виявлення, групування та сортування

## Базовий алгоритм

Для кожної серії, яка має книгу в черзі або активному читанні:

1. Завантажити всі відомі книги серії для поточного користувача.
2. Відсортувати їх чинним канонічним helper-ом.
3. Нормалізувати reading status через спільну доменну логіку.
4. Побудувати map із:
   - фактом перебування в черзі;
   - `queuePosition`;
   - фактом активного читання;
   - ownership;
   - станом ignore;
   - станом disable для серії.
5. Для кожної книги, яка в черзі або читається, знайти всі попередні книги серії.
6. Відкинути закриті попередні книги.
7. Знайти першу актуальну попередню книгу та кількість усіх незакритих попередніх.
8. Визначити `problemType`.
9. Побудувати current і recommended order.
10. Згрупувати всі конфлікти в один issue item на серію.
11. Обрати головний конфлікт за severity і ranking.
12. Додати summary про інші конфлікти цієї ж серії.
13. Відкинути issues, які проігноровано для поточного fingerprint.
14. Стабільно відсортувати результати.
15. Застосувати `limit` лише після повного ранжування.

## Групування

Одна серія повертається один раз.

Приклад summary:

```text
Серія «Вище неба»
Перед книгою 4 залишилося 2 незакриті частини.
Наступна за порядком — книга 2.
```

Якщо у серії одночасно кілька проблем:

- одна стає `primaryProblem`;
- інші повертаються у `relatedProblems` або агрегованому summary;
- frontend не створює окремі sidebar-картки для тієї ж серії.

## Severity

### `error`

Фактичний порядок уже порушено:

- `current_reading_ahead_of_order`;
- `previous_book_after_later_book`;
- `multiple_books_out_of_order`.

### `warning`

Попередня книга не завершена, відсутня або недоступна:

- `missing_previous_from_queue`;
- `multiple_previous_missing`;
- ownership-проблеми.

### `info`

Попередня книга на паузі:

- `previous_book_paused`.

## Порядок важливості

1. `current_reading_ahead_of_order`
2. `previous_book_after_later_book`
3. `multiple_books_out_of_order`
4. `multiple_previous_missing`
5. `missing_previous_from_queue`
6. `previous_book_paused`
7. ownership-проблеми

У межах одного рівня:

1. найменша позиція проблемної книги в черзі;
2. найменша канонічна позиція першої актуальної попередньої книги;
3. стабільний `seriesId`.

## Детермінованість

Повторні запити до незміненої черги мають повертати:

- однаковий набір issues;
- однаковий `primaryProblem`;
- однаковий порядок;
- однаковий fingerprint.
