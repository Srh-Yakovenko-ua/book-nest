# Edge cases та правила перерахунку

## Пропуск номера

```text
1 → 2 → 4 → 5
```

Якщо книги 3 немає у базі або каталозі серії, не створювати її та не показувати warning. Канонічний порядок відомих книг: `1 → 2 → 4 → 5`.

## Дробові позиції

```text
1 → 1.5 → 2
```

Не округлювати позицію. Використати фактичний тип поля та чинний comparator.

Якщо поточна schema підтримує лише цілі значення, backend-аудит має це зафіксувати; агент не повинен непомітно змінювати всю модель серій лише в межах цього блока.

## `null` у позиції

1. Використати чинний fallback із модуля серій, якщо він існує.
2. Якщо fallback немає, книгу з `null` не використовувати як попередню, коли це може створити хибний warning.
3. Логувати data-quality issue.
4. Якщо порядок усієї серії ненадійний, не повертати issue для неї.

## Дублікати позицій

Використати чинний стабільний tiebreaker. Якщо його немає, рекомендовано:

```text
publishedAt → id
```

Не виконувати недетерміноване сортування.

## Книгу видалено з черги

Issues перераховуються. Старий fingerprint більше не застосовується.

## Книгу прибрали із серії

Issues перераховуються на основі нового складу серії.

## Серію видалено

Пов’язані issues та user preferences мають бути коректно очищені або перестати повертатися.

## Книга вже є в черзі під час apply

Не створювати duplicate. Повернути ідемпотентний результат або доменну помилку `ALREADY_IN_QUEUE`, після якої frontend виконує refetch.

## Черга досягла ліміту

Операція додавання не застосовується частково. Повернути доменну помилку `QUEUE_LIMIT_REACHED`.

## Зміна статусу після отримання issue

Якщо reading status змінився між отриманням issue і apply, backend має повторно перевірити умови. Якщо issue вже неактуальний, повернути `409` або спеціальний код `ISSUE_STALE`.

## Кілька вкладок або пристроїв

Усі queue mutations перевіряють `expectedQueueVersion`, ETag або еквівалентний механізм optimistic concurrency.

## Дуже довгі назви та відсутня обкладинка

API повертає повний текст і `null` для відсутньої обкладинки. Truncation та placeholder належать frontend.

## Ізоляція користувачів

Усі книги, черга, statuses, ignores і preferences обмежуються поточним authenticated user. `userId` не приймається з query/body як джерело доступу.
