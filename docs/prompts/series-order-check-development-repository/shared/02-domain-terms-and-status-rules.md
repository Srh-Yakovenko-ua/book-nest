# Терміни та правила статусів

## Канонічний порядок серії

Це порядок книг, визначений доменною моделлю серії.

Джерело істини має бути тим самим, яке вже використовується:

- у деталях серії;
- у списку книг серії;
- у поточній логіці `nextBook`;
- у repository/domain helpers.

Можливі назви поля:

```text
seriesPosition
bookNumber
volumeNumber
sequence
order
```

Фактичне поле та його тип визначаються під час аудиту.

Заборонено використовувати як канонічний порядок:

```text
createdAt
updatedAt
дату додавання до черги
дату додавання книги
алфавіт
queuePosition
queuePriority
```

## Фактичний порядок черги

Це порядок, який бачить користувач. Джерелом істини є `queuePosition` або еквівалентне поле поточного queue API.

Активне читання для аналізу вважається умовною позицією `0`, тобто логічно знаходиться перед усіма книгами черги.

## Закриті статуси

Рекомендоване правило:

```text
finished
dnf
```

- `finished` — книга завершена.
- `dnf` — користувач свідомо припинив читання; книга не є прочитаною для статистики, але не блокує наступну частину.

Якщо в коді вже існує спільний доменний helper із іншою семантикою `dnf`, не створювати локальне правило. Використати чинну семантику й зафіксувати її в аудиті.

## Незакриті статуси

```text
not_started
want_to_read
reading
paused
```

Вони можуть створювати конфлікт порядку.

## Проблемна книга

Книга, яка:

- перебуває в черзі або зараз читається;
- має перед собою щонайменше одну незакриту відому книгу серії.

## Перша актуальна попередня книга

Найраніша незакрита книга за канонічним порядком перед проблемною книгою.

Приклад:

```text
1 — finished
2 — not_started
3 — not_started
4 — у черзі
```

Першою актуальною попередньою є книга 2.

## Ownership та доступність

Очікувані стани:

```text
NONE
WANT_TO_BUY
IN_TRANSIT
OWNED
BORROWED_FROM
LENT_TO
```

Ownership не визначає правильність канонічного порядку, але визначає пояснення та доступну дію для попередньої книги.
