# 02. Аудит фактичної бекенд-реалізації

> Містить розділ 4. Цей файл потрібно опрацювати до початку фронтенд-реалізації.

## 4. Обов’язковий аудит перед реалізацією

Бекенд-агент спочатку має перевірити й задокументувати актуальний стан.

### 4.1. Перевірити модель серії

Знайти:

- модель `Series`;
- зв’язок книги із серією;
- поле позиції книги;
- підтримку дробових номерів, новел, пріквелів, спін-офів;
- унікальні обмеження;
- сортування книг серії;
- статус серії;
- спосіб визначення загальної кількості книг.

### 4.2. Перевірити поточну логіку «наступної книги»

Знайти, чи вже існують:

- domain helper;
- service method;
- repository query;
- computed field;
- endpoint для series details;
- логіка `nextBook`;
- логіка першої непрочитаної книги.

Якщо така логіка є, її потрібно винести або повторно використати. Не створювати другий алгоритм із трохи іншими правилами.

### 4.3. Перевірити джерело статусу читання

З’ясувати:

- чи статус зберігається на `Book`;
- чи він обчислюється з `BookReadingProgress`;
- чи може бути кілька сесій читання;
- чи можливі суперечливі дані;
- що є джерелом істини.

### 4.4. Перевірити улюбленість

Поточна відома логіка:

```prisma
isFavorite      Boolean
favoriteAddedAt DateTime?
```

Перевірити, чи не було змінено модель в актуальній гілці.

### 4.5. Перевірити статуси володіння

З’ясувати:

- де зберігається ownership;
- чи одна книга може мати кілька екземплярів;
- чи `LENT_TO` означає, що книга є у власності, але тимчасово недоступна;
- чи `BORROWED_FROM` вважається доступною для читання;
- чи `NONE` означає, що Book-запис уже існує, але немає фізичного/цифрового екземпляра.

### 4.6. Перевірити видимість «відсутніх» книг серії

Критично встановити:

- чи всі книги серії існують як `Book` користувача;
- чи серія має окремий каталог `SeriesBook`;
- чи можна знати про книгу, якої ще немає серед користувацьких `Book`;
- чи ownership `NONE` уже покриває такий випадок.

Не синтезувати книгу, якої немає в базі та для якої немає каталожного запису.

### 4.7. Формат звіту аудиту

Перед змінами надати:

```text
Уже є:
- ...

Немає:
- ...

Канонічний порядок книг:
- ...

Джерело статусу читання:
- ...

Поточна логіка nextBook:
- ...

Модель відсутньої книги серії:
- ...

Рекомендоване місце нового endpoint:
- ...
```
