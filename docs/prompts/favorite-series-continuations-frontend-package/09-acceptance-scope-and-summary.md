# 09. Acceptance criteria, межі задачі та підсумкова логіка

> Містить розділи 38–41. Використовується як фінальний checklist перед завершенням.

## 38. Acceptance Criteria — бекенд

- [ ] Проведено аудит поточної моделі серій і next-book логіки.
- [ ] Використано канонічний порядок серії.
- [ ] Серія потрапляє до блока лише за наявності улюбленої книги.
- [ ] Одна серія повертається один раз.
- [ ] Наступна книга визначається як перша актуальна в усій серії.
- [ ] Пізніша улюблена книга не змушує пропускати ранню непрочитану.
- [ ] `finished` не блокує рух.
- [ ] Поведінку `dnf` явно зафіксовано й покрито тестами.
- [ ] Серії без наступної відомої книги не повертаються.
- [ ] Серії з однієї книги не повертаються.
- [ ] Ownership впливає на ranking.
- [ ] Активне читання має найвищий пріоритет.
- [ ] Результат стабільно відсортований.
- [ ] Є limit для sidebar.
- [ ] Немає N+1.
- [ ] Дані ізольовані за користувачем.
- [ ] Endpoint повертає серію, progress і nextBook.
- [ ] Не повертаються локалізовані UI-тексти.
- [ ] Додано unit та integration/e2e тести.
- [ ] Старі endpoints серій і книг не зламані.

## 39. Acceptance Criteria — фронтенд

- [ ] Блок показується у правому барі сторінки «Улюблені книги».
- [ ] Показується не більше трьох серій.
- [ ] Дані відображаються в порядку backend.
- [ ] Для кожної серії показано правильну наступну книгу.
- [ ] Показано назву серії та позицію книги.
- [ ] Ownership chip відповідає фактичному статусу.
- [ ] Reading status і прогрес показуються для `reading`/`paused`.
- [ ] CTA відповідає reading та ownership.
- [ ] Для `NONE` є дія «Додати до “Хочу купити”».
- [ ] Для `WANT_TO_BUY` немає повторного додавання.
- [ ] Для `IN_TRANSIT` немає дії покупки.
- [ ] Для книги в черзі не показується повторне «Додати в чергу».
- [ ] Після mutation блок оновлюється.
- [ ] Реалізовано loading, error та empty states.
- [ ] Блок не ламає адаптивність.
- [ ] Використані наявні theme tokens і компоненти.
- [ ] Усі тексти винесено в i18n.
- [ ] Додано frontend tests.

## 40. Що не входить у задачу

Не потрібно:

- створювати окремий прапорець `isFavorite` для серії;
- автоматично позначати всю серію улюбленою;
- робити рекомендації на основі жанрів;
- показувати випадкову книгу;
- створювати записи майбутніх книг, яких немає в системі;
- автоматично додавати книги до wishlist;
- автоматично купувати або змінювати ownership;
- змінювати статус читання без явної дії;
- створювати нову чергу читання;
- переписувати весь модуль серій;
- дублювати на фронтенді алгоритм визначення nextBook;
- визначати nextBook лише з трьох завантажених книг;
- рахувати результат у браузері з поточної сторінки пагінації.

## 41. Підсумкова логіка

Для кожної серії:

```text
1. Є хоча б одна улюблена книга?
   Ні → виключити.

2. У серії щонайменше 2 книги?
   Ні → виключити.

3. Можна визначити канонічний порядок?
   Ні → виключити або використати чинний безпечний fallback.

4. Знайти першу книгу, статус якої не є закритим.
   Немає → серію завершено, виключити.

5. Визначити reading status, ownership, queue та progress.

6. Призначити rank:
   reading
   → paused
   → доступна зараз
   → позичена комусь
   → у дорозі
   → хочу купити
   → немає у власній бібліотеці.

7. Відсортувати серії стабільно.

8. Повернути перші 3 для правого бара.
```

Головний принцип:

> Блок має показувати не книгу після улюбленої, а **реальну наступну книгу за прогресом користувача в усій серії**.
