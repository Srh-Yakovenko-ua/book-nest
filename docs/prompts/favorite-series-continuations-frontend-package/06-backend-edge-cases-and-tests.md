# 06. Backend edge cases і тести

> Містить розділи 20–21. Використовується для перевірки повноти фактичної реалізації.

## 20. Backend edge cases

### 20.1. У серії немає улюблених книг

Не повертати серію.

### 20.2. Є улюблена книга, але вона більше не належить серії

Після зміни зв’язку серія має зникнути з результату, якщо інших улюблених книг у ній немає.

### 20.3. Книга видалена

Не враховувати soft-deleted або hard-deleted записи відповідно до чинної моделі.

### 20.4. Серія видалена

Не повертати її.

### 20.5. Усі книги `finished`

Не повертати серію.

### 20.6. Усі книги `dnf`

За рекомендованим правилом серія закрита — не повертати.

### 20.7. Перша книга `reading`, наступні `finished`

Показувати першу книгу зі статусом `reading`.

Не пропускати її лише через те, що пізніші книги вже завершено.

### 20.8. Розірваний порядок

```text
1 finished
3 not_started
```

Показувати книгу 3. Не вигадувати книгу 2.

### 20.9. Пізніша книга вже прочитана, рання — ні

Показувати ранню непрочитану.

### 20.10. Книга без ownership

Якщо `null` неможливий за schema — не обробляти як нормальний стан.

Якщо можливий legacy `null`, нормалізувати до `NONE` у mapper або domain helper.

### 20.11. Книга без reading status

Якщо default існує — використовувати його.

Якщо можливий legacy `null`, нормалізувати до `not_started`.

### 20.12. Немає обкладинки

Повертати `null`; фронтенд показує стандартний placeholder.

### 20.13. Немає автора

Повертати порожній список або чинний fallback. Не падати.

### 20.14. Дуже довга назва

API не обрізає текст; frontend керує truncation.

### 20.15. Дуже багато серій

Endpoint має підтримувати limit і, за потреби, пагінацію.

### 20.16. `limit = 0`, від’ємний або занадто великий

Використати shared validation:

- мінімум 1;
- максимум за чинними правилами, наприклад 50;
- default 3 для sidebar endpoint або явний limit із фронтенду.

### 20.17. Серія з однієї книги

Якщо єдина книга не завершена й улюблена, технічно вона відповідає критеріям, але це не «продовження серії».

Рекомендоване правило:

```text
series.totalBooks >= 2
```

Серії з однієї книги не показувати в цьому блоці.

### 20.18. Серія позначена завершеною, але має непрочитану книгу

Показувати, бо статус серії не означає, що користувач її завершив.

### 20.19. Серія ще виходить, усі відомі книги завершено

Не показувати, доки в системі не з’явиться наступна відома книга.

### 20.20. Книга вже в черзі

Повертати queue metadata, якщо воно доступне. Frontend не має пропонувати «Додати в чергу» повторно.

## 21. Backend тести

### 21.1. Вибір серій

- серія з однією улюбленою книгою потрапляє;
- серія без улюблених не потрапляє;
- кілька улюблених книг не дублюють серію;
- соло-книга не потрапляє;
- серія з однієї книги не потрапляє.

### 21.2. Вибір наступної книги

- перша `not_started`;
- перша `want_to_read`;
- перша `reading`;
- перша `paused`;
- `finished` пропускається;
- `dnf` пропускається за обраним правилом;
- рання непрочитана має пріоритет над пізнішою улюбленою;
- усі закриті → серія відсутня.

### 21.3. Ownership і rank

Перевірити порядок:

```text
reading
paused
OWNED/BORROWED_FROM
LENT_TO
IN_TRANSIT
WANT_TO_BUY
NONE
```

### 21.4. Tiebreakers

- новіший `favoriteAddedAt` вище;
- однакові дати стабілізуються `seriesId`;
- повторні запити повертають однаковий порядок.

### 21.5. Ізоляція користувача

- чужі favorites не враховуються;
- чужі reading statuses не враховуються;
- чужі ownership не враховуються.

### 21.6. Порядок серії

- integer positions;
- fractional positions;
- gaps;
- duplicates;
- null;
- stable fallback.

### 21.7. Контракт

- `total`;
- `items`;
- `nextBook`;
- `progress`;
- `favoriteBooksCount`;
- nullable cover;
- authors;
- validation limit.
