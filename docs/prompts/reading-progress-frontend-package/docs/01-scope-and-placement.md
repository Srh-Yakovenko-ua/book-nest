# 1. Scope і розміщення на сторінці

## Що реалізувати

1. Оновлений компактний блок **«Прогрес читання»**.
2. Підтабу **«Повна історія читання»** у межах деталей конкретної книги.
3. Summary, activity chart, recent activity, day groups, events, sort і server-side pagination.
4. Loading, refetch, error, empty, legacy та partial-data states.
5. UA/EN локалізацію, responsive layout, accessibility та тести.

## Нове місце блока

Поточний блок знаходиться у правому сайдбарі. Це потрібно змінити.

Цільова структура основної частини сторінки:

```text
[Header книги]
[Основні відомості / метадані]
[Блок «Про книгу»]
[Блок «Прогрес читання» або «Підсумок читання»]
[Наступні секції сторінки]
```

Вимоги:

- блок рендериться у головній контентній колонці;
- знаходиться безпосередньо під «Про книгу»;
- не рендериться паралельно у sidebar;
- sidebar після перенесення не повинен містити порожню оболонку або зайвий placeholder;
- ширина блока відповідає ширині основного контенту;
- chart і summary використовують додатковий простір основної колонки;
- на mobile блок залишається в природному потоці після «Про книгу».

## Підтаба

Назва:

- UA: `Повна історія читання`
- EN: `Full reading history`

Підтаба:

- використовує поточний `bookId`;
- не є окремою глобальною сторінкою;
- інтегрується в наявну систему табів/підтабів;
- синхронізується з URL, якщо це вже прийнято в проєкті;
- після reload лишається відкритою, якщо інші таби вже URL-driven.

## Не входить у scope

- зміна backend-логіки або DTO;
- створення нової дизайн-системи;
- додавання нової chart library без потреби;
- frontend-агрегації історії;
- нові глобальні сторінки;
- нові empty-state ілюстрації;
- редизайн усієї сторінки деталей книги поза необхідним перенесенням блока.
