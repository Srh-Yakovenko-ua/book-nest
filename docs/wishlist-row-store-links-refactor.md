# Спека — одне меню в картці списку бажань і діалог «Магазини та ціни»

## 1. Проблема

Заміряно на живій сторінці з 33 книгами (dev-акаунт, 40 посилань):

| Показник                       | Значення                                        |
| ------------------------------ | ----------------------------------------------- |
| Фокусованих елементів у рядках | **180**                                         |
| На один рядок                  | мін. 3 · сер. 5.5 · **макс. 10**                |
| Меню на екрані                 | **73** (40 «дії для посилання» + 33 «інші дії») |
| Посилань на магазини           | 40                                              |

Найгірший рядок — «Це зіткане королівство» з чотирма посиланнями:

```
назва → Yakaboo → ⋮ → Книгарня «Є» → ⋮ → Readeat → ⋮ → Ще 1 → Оновити статус → …
```

Щоб клавіатурою дійти від першої книги до третьої, треба п'ятнадцять разів натиснути Tab.

### Чотири накладені дефекти

1. **Два меню, візуально нерозрізненні.** Обидва — іконка `more`; різниця лише в розмірі (12px проти 16px). Здогадатися, що `⋮` біля ціни редагує саме це посилання, а `…` в кінці додає нове, без відкриття обох неможливо.

2. **Список посилань несе дві несумісні ролі** — дані для порівняння **і** поверхня редагування. Через це кожен елемент мусить бути і посиланням (відкрити магазин), і носієм меню. Це першопричина щільності, а не самі меню.

3. **Обрізаний список ховає головне.** `VISIBLE_LINKS_LIMIT = 3` (`store-links-list.tsx:18`), а бек віддає посилання `orderBy: { createdAt: "asc" }` (`book-store-link.repository.ts:79`) — у порядку додавання, **не за ціною**. Якщо найдешевше додали четвертим, у згорнутому рядку видно три магазини й жодної зеленої підсвітки. Сторінка, суть якої — показати найвигіднішу пропозицію, у цьому випадку її ховає.

4. **Колонка не тримає навантаження**: `sm:w-56 md:w-64` — 224–256px на список, у якому за контрактом може бути до `MAX_STORE_LINKS_PER_BOOK = 20` посилань.

| Файл                                                             | Роль                                                         |
| ---------------------------------------------------------------- | ------------------------------------------------------------ |
| `features/books-to-buy/components/books-to-buy-row.tsx`          | рядок: назва, `StoreLinksList`, кнопка статусу, меню `…`     |
| `features/books-to-buy/components/store-links-list.tsx`          | список посилань, ліміт 3 + «Ще N», підсвітка найкращого      |
| `features/books-to-buy/components/store-link-menu.tsx`           | `⋮` на кожному посиланні: редагувати / видалити              |
| `features/books-to-buy/components/store-link-dialog.tsx`         | форма створення й редагування посилання                      |
| `features/books-to-buy/components/book-store-links-block.tsx`    | **сторінка книги** — використовує той самий `StoreLinksList` |

**`StoreLinksList` спільний для двох поверхонь.** Якщо просто прибрати з нього меню, сторінка книги втратить редагування — тому діалог має обслуговувати обидві.

## 3. Рішення — рядок

Рядок стає **лише для читання**. Усе редагування переїжджає в діалог.

```
┌──────────────────────────────────────────────────────────────┐
│ [обкл] Це зіткане королівство    🏷 Readeat 449 грн           │
│        Тагере Мафі                  ще 3 магазини             │
│                                   [Оновити статус]   [ … ]    │
└──────────────────────────────────────────────────────────────┘
```

- **Чип найкращої пропозиції** — посилання, що відкриває магазин у новій вкладці. Один факт, заради якого на цю колонку дивляться.
- **«ще 3 магазини»** — кнопка, що відкриває діалог. Не рендериться, коли посилання одне.
- `⋮` біля посилань **зникають повністю**.

Табстопів на рядок: **10 → 4**. По сторінці: **180 → ~100**.

### 3.1 Стани колонки

| Стан книги                            | Що показує рядок                                   |
| ------------------------------------- | -------------------------------------------------- |
| немає посилань                        | наявний текст «Посилання на магазини ще не додані» |
| є посилання, жодне без ціни           | чип найкращої + «ще N магазинів»                   |
| є посилання, **у жодного немає ціни** | кнопка «N магазинів · ціни не вказані», без чипа   |
| рівно одне посилання з ціною          | лише чип, без «ще N»                               |

## 4. Пастка з валютами — обов'язково прочитати

`computeBestOffer` (`apps/api/src/modules/books/domain/best-offer.ts:10`) працює так:

1. знаходить найдешевше посилання **в межах кожної валюти**;
2. повертає першу валюту за порядком енама `CurrencySchema.options` = **UAH → EUR → USD**;
3. нічия в межах валюти розв'язується раннішим `createdAt`.

Це **не** «найдешевше загалом». Для книги з КСД 390 ₴ і Blackwell's 12,5 € (≈550 ₴) поверне 390 ₴ не тому, що дешевше, а тому, що UAH стоїть в енамі першою. Курсів валют у застосунку немає, і додавати їх у цьому заході ми не будемо.

Поки видно весь список, користувач судить сам. Щойно в рядку лишиться одна ціна — вона почне робити заяву, якої домен не робить.

**Через це:**

- чип **не** підписується як «найкраща ціна» чи «найдешевше» в рядку — він показує пропозицію без оцінного слова;
- якщо в книги є посилання **більш ніж в одній валюті**, кнопка поруч читається «ще N магазинів · інші валюти» — сигнал, що порівняння неповне й варто відкрити діалог;
- усередині діалогу підсвітка «найдешевше» ставиться **лише в межах валюти чипа** і супроводжується поясненням.

Домен не змінюємо: правило вибору вже узгоджене зі зведенням у сайдбарі (`wishlist-summary.ts`), і міняти його тут означало б розсинхронити картку зі статистикою.

## 5. Рішення — діалог «Магазини та ціни»

```
┌────────────────────────────────────────────────────┐
│  Магазини та ціни                            4/20  │
│  «Це зіткане королівство»                          │
│                                                    │
│  🏷 Readeat            449 грн   найдешевше  ✎  🗑 │
│     readeat.com/this-woven-kingdom                 │
│     Книгарня «Є»       470 грн               ✎  🗑 │
│     book-ye.com.ua/…                               │
│     Yakaboo            512 грн               ✎  🗑 │
│     Наш Формат         528 грн               ✎  🗑 │
│                                                    │
│  [+ Додати посилання]                   [Закрити]  │
└────────────────────────────────────────────────────┘
```

### 5.1 Чому модалка, а не поповер чи inline-розгортання

**Поповер із тригера `…`** — відпадає. До 20 рядків із ціною, валютою і двома діями не влазять, а вкладені меню в поповері дають ту саму плутанину, від якої тікаємо.

**Inline-розгортання рядка** — відпадає. Рядок виростає на 20 позицій і зсуває всі книги нижче; у списку з 33 карток це втрата місця в прокрутці. Плюс редагування всередині рядка знову змішує читання й редагування — та сама вада, що зараз.

**Окремий діалог** — беремо:

- є місце показати повний запис, включно з URL, якого зараз ніде не видно;
- єдиний спосіб дати клавіатурному користувачу дійти до редагування, не проходячи 40 табстопів;
- **обслуговує і сторінку книги** — тобто це не додаткова робота, а прибирання дублювання.

### 5.2 Рядок усередині діалогу

Дій рівно дві, тому **явні іконки-кнопки** «редагувати» й «видалити», а не меню. Меню на два пункти — обгортка над нічим, і саме такий шар ми зараз прибираємо.

- назва магазину — посилання, відкриває магазин у новій вкладці (`isHttpsUrl` перевіряється, як зараз у `store-links-list.tsx:112`);
- URL — другим рядком, приглушено, з обрізанням;
- ціна з валютою через наявний `formatStorePrice`;
- бейдж «найдешевше» — лише на посиланні, що збігається з `bestOffer` (той самий `findBestOfferLinkId`);
- видалення йде через наявний `useDeleteStoreLinkWithUndo` — тост зі «Скасувати» лишається.

Порожній стан діалогу: «Посилань ще немає» + кнопка додавання.

### 5.3 Сортування

Список у діалозі сортується **на клієнті**: за ціною за зростанням, посилання без ціни — в кінці за `createdAt`. Різні валюти сортуються групами в порядку `CurrencySchema.options`, бо порівнювати їх напряму нічим.

Контракт бекенду (`createdAt asc`) **не змінюється** — 20 елементів сортуються на клієнті без затрат, а стабільний порядок з API лишається передбачуваним для інших споживачів.

### 5.4 Створення й редагування

Наявний `StoreLinkDialog` перевикористовується як є, у режимах `create` і `edit`. Він відкривається **поверх** діалогу списку; після збереження список оновлюється, діалог списку лишається відкритим.

## 6. Меню рядка

Одне меню `…` в кінці, два пункти:

| Пункт                  | Дія                                    | Коли ховається                       |
| ---------------------- | -------------------------------------- | ------------------------------------ |
| Магазини та ціни ({n}) | відкриває діалог списку                | коли посилань немає                  |
| Додати посилання       | відкриває `StoreLinkDialog` у `create` | на ліміті `MAX_STORE_LINKS_PER_BOOK` |

Якщо обидва пункти сховані (посилань немає і ліміт вичерпано — взаємно неможливо, але перевірити), тригер не рендериться. Ширина — `className="w-56"`, бо пункт із лічильником довший за поточний.

Кнопка «Оновити статус» лишається окремою primary-кнопкою поза меню.

## 8. Вплив на сторінку книги

`BookStoreLinksBlock` (`book-store-links-block.tsx`) зараз показує `StoreLinksList` із меню на кожному посиланні плюс кнопку «Додати посилання».

Після зміни:

- блок показує список **без** `⋮` (місця на сторінці книги більше, тож тут лишається повний список, а не один чип);
- замість «Додати посилання» — кнопка «Магазини та ціни», що відкриває **той самий діалог**;
- редагування й видалення живуть лише в діалозі, як і в картці.

Це прибирає другу копію логіки редагування, а не додає її.

## 9. Доступність

- Чип найкращої пропозиції — `<a>` з наявним `sr-only` «(відкриється в новій вкладці)».
- «ще N магазинів» — `<button>`, не `<a>`: вона нічого не навігує, а відкриває діалог.
- Список у діалозі — `<ul>` з `aria-label` із заголовка; кожен рядок `<li>`.
- Кнопки «редагувати» й «видалити» — `aria-label` з назвою магазину, інакше скрінрідер почує «редагувати» чотири рази поспіль.
- Підказка про валюти — не `title`, а видимий текст під заголовком: `title` недоступний з клавіатури й на тач-екранах.
- Після видалення фокус переходить на наступний рядок списку, а якщо він був останнім — на кнопку додавання.
- Діалог редагування відкривається поверх діалогу списку; після закриття фокус повертається на кнопку, з якої його відкрили.

## 10. Тести

Компонентні, Vitest + RTL, мок на межі `fetch`, `renderWithProviders`. Ніколи не мокати хуки TanStack Query.

**Рядок:**

- показує чип найкращої пропозиції й кнопку «ще N магазинів»;
- при одному посиланні кнопки «ще» немає;
- при посиланнях без цін показує «N магазинів · ціни не вказані» замість чипа;
- при посиланнях у різних валютах показує варіант «інші валюти»;
- у рядку немає жодного `⋮` посилання (пін проти регресії);
- меню `…` веде і в діалог списку, і у форму додавання.

**Діалог:**

- показує всі посилання, включно з тими, що були за межею «Ще N»;
- сортує за ціною; посилання без ціни — в кінці;
- бейдж «найдешевше» стоїть на посиланні, що збігається з `bestOffer`;
- підказка про валюти з'являється лише при кількох валютах;
- редагування відкриває `StoreLinkDialog` із заповненими полями й після збереження оновлює рядок у списку;
- видалення прибирає рядок і показує тост зі «Скасувати»;
- на ліміті 20 кнопка додавання зникає;
- порожній стан показує «Посилань ще немає».

**Сторінка книги:** `BookStoreLinksBlock` не рендерить `⋮`, а його кнопка відкриває той самий діалог.

## 11. Ухвалені рішення

1. **Рядок показує одну найкращу пропозицію**, не три. Порівняння всередині книги переїжджає в діалог, де для нього є місце.
2. **Список посилань — окремий діалог**, не поповер і не inline-розгортання.
3. **Дії в діалозі — явні іконки**, не меню: дій рівно дві.
4. **Домен `computeBestOffer` не змінюється.** Натомість тексти в рядку перестають робити заяву про «найдешевше», якої алгоритм не підтверджує.
5. **Порядок з API (`createdAt asc`) не змінюється**, сортування за ціною — на клієнті.
6. **Сторінка книги переходить на той самий діалог** у цьому ж заході, інакше залишиться друга копія логіки редагування.

## 12. Поза межами

- Курси валют і зведення різних валют до однієї. Це окрема задача з зовнішнім джерелом курсів.
- Зміна контрактів API або схеми БД — усі потрібні ендпоінти вже є.
- Масові дії над посиланнями (видалити всі, імпорт) — потреби не заявлено.
