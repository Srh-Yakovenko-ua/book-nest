# Бекенд-завдання: дані для мікрофактів stat-карток «Усі книги»

## Навіщо (контекст)

На сторінці **«Усі книги»** редизайнимо 4 stat-картки (Усього книг / Читаю / Прочитано / Улюблених). Крім числа, кожна картка отримує **мікрофакт** — третій рядок із коротким змістовним фактом. Фронт уже готовий їх рендерити, але сторінка вантажить лише одну сторінку пагінації (24 з 138 книг), тож порахувати мікрофакти на клієнті **неможливо** — потрібна агрегація по всій бібліотеці на беку.

Це завдання **суто про дані**: ендпоінт `GET /api/books/overview` має додати кілька агрегованих полів. Верстку/переклади чіпати не треба.

## Поточний стан

`GET /api/books/overview` повертає `summary: { total, reading, finished, favorites }` (+ `recentlyAdded`, `topGenres`, `topTags`). Мікрофакт «Улюблених» (`favorites/total`) фронт рахує сам із наявного — **його додавати не треба**. Бракує даних для трьох інших карток.

## Головна вимога (scope)

Усі нові поля рахуються **в тому самому `owner`-scope**, що вже приходить у query overview (порожній owner = вся бібліотека користувача; на «Моїй бібліотеці» — owned/lent/borrowed). Тобто мікрофакт має збігатися з тим, що юзер реально бачить на цій сторінці.

## Що додати у відповідь `overview`

Усі поля — **опціональні та адитивні** (не ламають наявний контракт). Контракт уже описано у `packages/shared` як опціональні поля (див. нижче) — треба їх заповнити.

### 1. Картка «Усього книг» → мікрофакт «{S} серій · {A} авторів»

| Поле (в `summary`) | Тип      | Що рахує (у межах scope)                      |
| ------------------ | -------- | --------------------------------------------- |
| `seriesCount`      | `number` | к-сть **унікальних серій**, у яких є ≥1 книга |
| `authorsCount`     | `number` | к-сть **унікальних авторів** по всіх книгах   |

- Унікальність — за id серії / id автора (не за назвою).
- Книга може мати кількох авторів — рахувати distinct по всіх зв'язках книга-автор у scope.

### 2. Картка «Читаю» → прогрес / «{N} книги · {P} стор. попереду»

Додати об'єкт `activeReading` (top-level, опціональний):

| Поле                       | Тип                                              | Значення                                                                                                                                                  |
| -------------------------- | ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `activeReading.pagesAhead` | `number`                                         | сума сторінок, що лишилось дочитати по **всіх активних книгах**: `Σ max(0, pagesCount − currentPage)`, лише де `pagesCount` відоме й `currentPage` відоме |
| `activeReading.book`       | `{ id, title, currentPage, pagesCount } \| null` | дані **єдиної** активної книги — non-null **тільки** якщо активних рівно 1 і в неї відоме `pagesCount`; інакше `null`                                     |

- «Активна книга» = `readingStatus ∈ (reading, rereading)`. Кількість активних = наявний `summary.reading`.
- `activeReading.book` потрібен фронту для прогрес-бару в кейсі «рівно 1 активна книга» (показує `{currentPage} з {pagesCount} · {%}`).
- Книги без `pagesCount` не входять у `pagesAhead` (не спотворюють суму); але враховуються у `summary.reading` — це нормально.

### 3. Картка «Прочитано» → мікрофакт «{P}% наявних книг»

| Поле (в `summary`)    | Тип      | Що рахує (у межах scope)                                                         |
| --------------------- | -------- | -------------------------------------------------------------------------------- |
| `physicallyAvailable` | `number` | к-сть книг з `ownershipStatus ∈ (owned, lent_to_someone, borrowed_from_someone)` |

- Це **знаменник** для «% прочитаних серед фізично наявних»: фронт рахує `round(finished / physicallyAvailable × 100)`.
- Знаменник = фізично наявні (у наявності + видано комусь + позичено у когось), **не вся бібліотека**.
- Якщо `physicallyAvailable = 0` — просто повернути `0`; ділення на нуль обробляє фронт (ховає рядок).

## Контракт у `packages/shared`

Поля вже додані як опціональні в `LibraryOverviewViewSchema` (файл `packages/shared/src/books.ts`):

```
summary: {
  ...наявні (total, reading, finished, favorites),
  authorsCount?: number,
  physicallyAvailable?: number,
  seriesCount?: number,
}
activeReading?: {
  pagesAhead: number,
  book: { id: string, title: string, currentPage: number, pagesCount: number } | null,
}
```

Треба лише **заповнити** їх у сервісі/репозиторії. Поки поле не приходить — фронт ховає відповідний мікрофакт (нічого не ламається).

## Обмеження / як робити (за архітектурою проєкту)

- Шарувата архітектура:
  - **репозиторій** (`books.repository.ts`) — єдиний шар з Prisma. `seriesCount`/`authorsCount` — distinct-агрегації; `physicallyAvailable` — `book.count({ where })`; `activeReading` — вибірка активних книг (лише потрібні поля: id/title/currentPage/pagesCount) для суми та єдиної книги. Використовуй наявні хелпери побудови `where`, щоб scope збігався з рештою overview.
  - **сервіс** (`books.service.ts`, метод `overview`) — рахує через `Promise.all` (як уже зроблено для наявних лічильників), мапить у ViewModel.
  - **контролер** — без логіки.
- Це **read-only агрегації** — **міграції не потрібні**, схему БД не чіпати.
- Один запит на сторінку, паралельно через `Promise.all`.

## Definition of done

- `GET /api/books/overview` повертає `summary.seriesCount`, `summary.authorsCount`, `summary.physicallyAvailable` та `activeReading` (з коректним `book` для кейсу однієї активної книги).
- Значення scope-залежні (перевірити overview без `owner` і з `owner` як на «Моїй бібліотеці»).
- Тести `books.controller.overview.test.ts` (+ сервіс) покривають: непорожні набори, 0 (0 серій, 0 наявних, 0 активних), рівно 1 активну книгу (`book !== null`), кілька активних (`book === null`, коректний `pagesAhead`).
- Гейти зелені: `pnpm typecheck`, `pnpm lint`, `pnpm test`.

## Поза межами

- Форми множини (серій/авторів/книг), верстка карток, прогрес-бар, клікабельність, ховання порожніх рядків — **усе на фронті**, уже робиться. Мікрофакт «Улюблених» (`favorites/total`) — теж фронт, поля не треба.
