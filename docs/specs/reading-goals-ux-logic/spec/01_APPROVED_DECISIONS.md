## Додаткові погоджені властивості дизайну

- Стилі Book Nest: кремова підкладка, тепла теракота (`#9A5D36` як референс палітри), стриманий зелений, відповідні радіуси, шрифти, іконки й існуючі дизайн-токени; жодної сторонньої дизайн-системи.
- Першочергово зрозумілі метрики, менше повторів; не робити сторінку довшою за рахунок декоративних карток.
- Єдина компактна верхня частина для вкладок «Огляд», «Книги», «Історія». Вкладки залишаються наявним `PageTabs` із query-параметрами.
- Відображати повний функціонал існуючих трьох вкладок; жодна важлива операція чи дані не мають зникнути.
- Не вводити новий enum статусу checkpoint у API: `achievedAt`, `dueDate`, `status` уже дозволяють похідне відображення `achieved_late` на фронті.
- Не змінювати `pace: on_track` лише через `paceDeltaBooks=-0.4`: цей статус має встановлений допуск. Текстом показувати, що прогрес близький до плану, з невеликим відставанням.

## Інваріанти та обмеження

1. Ціль прив'язана до одного списку; **склад книг фіксується при створенні**. Пізніші зміни списку не змінюють snapshot.
2. Книга зараховується не більш ніж один раз, якщо завершена між створенням цілі та дедлайном включно, з урахуванням дати архівування.
3. Підтримуються `active`, `completed`, `expired`, `archived`; жоден статус не видаляти й не перейменовувати в API.
4. `on_track`, `ahead`, `behind`, `critical` залишаються існуючими темпами. Рівень ризику — окрема оцінка, не синонім темпу.
5. Архівована ціль read-only, залишається доступною у каталозі й деталях; видалення незворотне після підтвердження.
6. Усі сторінки продовжують підтримувати українську й англійську, keyboard navigation, a11y, loading/error/empty/filtered-empty.
7. Визначати «сьогодні» і дедлайн у часовій зоні профілю, а не браузерними нестабільними припущеннями.
8. Втрата книги/списку, часткові дані, 0 книг, 100% прогрес та історичні цілі не повинні ламати UI.
9. Не додавати пошук/новий API сортування в рамках цього рефактору: окрема майбутня фіча, поза затвердженим scope.

## Ризики, які треба контролювати

- Перевизначення `riskLevel` може змінити KPI «Потребують уваги», порядок `risk_desc` та статистику в інших модулях.
- Зміни метаданих старих `book_counted` впливають на історію: потрібен окремий idempotent-safe план виправлення, без мовчазної міграції користувацьких записів.
- `checkpoint.status=missed` може співіснувати з `achievedAt` після дедлайну конкретної точки: це свідомо розмежовані метрика своєчасності та факт досягнення.
- Дві колонки книг не повинні зламати нескінченну пагінацію або обкладинки різних пропорцій.
- Generated PNG не гарантують точності тексту: текст, числа й стани завжди брати з локалізації та API.
