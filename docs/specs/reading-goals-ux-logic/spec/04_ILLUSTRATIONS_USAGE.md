# Book Nest · Reading Goals — фінальні PNG-ілюстрації (v3)

До пакета входить **5 окремих PNG із прозорим фоном**, виконаних в узгодженому теплому акварельному стилі Book Nest. Вони призначені для використання у UI (на відміну від концептуальних макетів у `references/design/`).

| Файл                                  | Стан / призначення                  | Де показувати                                                                                                       |
| ------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `goal-first-goal-empty-state.png`     | Немає жодної створеної цілі         | Empty state загального каталогу `/goals`                                                                            |
| `goal-completed-trophy-books.png`     | Ціль виконано, 100%                 | Стриманий святковий стан у деталях завершеної цілі; за можливості повторне використання для «Найкращого результату» |
| `goal-forecast-insufficient-data.png` | Замало даних для надійного прогнозу | Компактний стан `projectionConfidence = none/low` у вкладці «Огляд»                                                 |
| `goal-no-counted-books-yet.png`       | Поки немає зарахованих книг         | Порожній стан фільтра «Зараховані» у вкладці «Книги»                                                                |
| `goal-expired-hourglass.png`          | Ціль прострочена / дедлайн минув    | Деталі простроченої цілі, лише коли статус `expired`                                                                |

## Обов'язкові правила реалізації

1. **Використовуй ці конкретні файли** як фінальні ілюстрації; не генеруй нові та не підміняй їх випадковими стоковими зображеннями. За потреби спершу перевір сумісність із чинними патернами `EmptyState` та `public/illustrations`.
2. Перенеси файли в `apps/web/public/illustrations/reading-goals/` (або в інше місце, яке відповідає поточним конвенціям проєкту), збережи пропорції та вихідну прозорість. Використовуй `next/image` або чинний компонент ілюстрації.
3. Для desktop орієнтуйся приблизно на **160–240 CSS px** у повноцінних empty state; для компактних інфоблоків — **80–140 CSS px**. На mobile зменшуй розмір адаптивно без горизонтального переповнення. Це орієнтири, а не абсолютні обмеження.
4. **Не додавай декоративні картинки до кожної KPI-картки чи рядка:** ілюстрації мають передавати спеціальний стан, не витісняти важливі метрики та доступні підписи.
5. Не відображай `goal-expired-hourglass.png` для активної цілі, навіть якщо прогнозуєш запізнення: це різні стани (`expired` ≠ projected late).
6. Якщо існує випробуваний reusable empty-state компонент, розширюй його мінімально; дотримуйся `prefers-reduced-motion`, `alt`/decorative alt, focus behavior, loading і responsive conventions.
7. Не змінюй зміст доменних статусів лише заради ілюстрації. Механіка визначається затвердженим ТЗ і фактичним API.
8. Перевір у Chrome MCP з доступним тестовим акаунтом усі 5 семантичних станів, якщо можливо; відсутні тестові стани відмічай як `NOT TESTED`, не змінюй production-дані.

## Структура пакетних ресурсів

- `references/design/` — 3 **концептуальні UI-ескізи**, використовувати як візуальні референси.
- `assets/illustrations/` — 5 **готових PNG-асетів**, використовувати у UI, а не як макети.
