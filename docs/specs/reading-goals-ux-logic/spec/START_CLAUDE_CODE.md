# Стартовий промпт для Claude Code — Book Nest / Reading Goals

Потрібно реалізувати затверджений рефактор Reading Goals. Пакет ТЗ розташовано в цій папці. Прочитай `00_README.md`, `01_APPROVED_DECISIONS.md`, `02_IMPLEMENTATION_SPEC.md`, `03_ACCEPTANCE_QA.md`, **`04_ILLUSTRATIONS_USAGE.md`**, звіт `references/audit/REPORT_2026-11-23.md`, три концептуальні PNG у `references/design/` та **5 готових прозорих PNG у `assets/illustrations/`**.

**Важливо:** це вже **задача на зміни коду**, на відміну від попереднього тестування через Chrome MCP. Усі UX/UI-рішення D01–D11 схвалено; за суперечності між PNG та ТЗ орієнтуйся на ТЗ й фактичний API. Уникай зайвих змін та нового функціоналу поза scope.

Порядок дій:

1. Перевір актуальний репозиторій, checkout і чистоту Git, онови посилання на актуальну `dev`. Від `dev` створи **одну окрему гілку `refactor/reading-goals-ux-logic` і перейди в неї; новий worktree НЕ створювати**. Не перезаписувати незакомічені зміни. Якщо branch уже існує, не перезаписувати, а обрати безпечне суфіксоване ім'я.
2. Зістав ТЗ з поточними `apps/api/src/modules/reading-goals`, `apps/web/src/features/reading-goals`, `packages/shared`, `messages/uk.json`, `messages/en.json`, статистикою та списками. Якщо щось уже реалізовано, пропусти дублювання.
3. Послідовно виконай етапи A→B→C→D→E→F з `02_IMPLEMENTATION_SPEC.md`. Виправ RG-01–RG-05, онови shared contract/generated API коректно, побудуй узгоджений UI 3 вкладок, мобільну версію та special states; **обов’язково інтегруй п’ять готових PNG за картою з `04_ILLUSTRATIONS_USAGE.md` (без повторної генерації)**. Не запускай build, ESLint і весь suite на проміжних етапах; не вводь нові залежності без потреби.
4. Не переписуй дані тестового/production-акаунта чи старі event metadata без окремої безпечної процедури й узгодженого dry-run. Для ризиків використай рекомендовані defaults v1 з ТЗ, але в підсумковому звіті явно зазнач, що це нова технічна деталізація; не змінюй формулу pace.
5. Після коду зроби **один фінальний** перевірочний прогін за `03_ACCEPTANCE_QA.md`: targeted tests, TS, lint changed files, мінімально потрібні build. Для UI-звірки використовуй Chrome MCP на доступному тестовому середовищі. Не здійснюй destructive/mutating дії на чужих даних.
6. Усунь знайдені помилки, підготуй повний звіт PASS/FAIL/BLOCKED та скріншоти. Зроби один фінальний commit у своїй гілці, якщо перевірки пройшли; **не роби merge у `dev` і не deploy**.

Працюй самостійно без зайвих погоджень. Якщо знайдеш реальний контрактний конфлікт, який не можна безпечно вирішити, зафіксуй його й виконай решту незалежних етапів, не підміняй проблему припущенням.
