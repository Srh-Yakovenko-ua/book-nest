### Strict checks

- **Merge.** Loser facts on dropped appearances are reparented by raw SQL before the delete, in the same transaction, read under the exclusive lock. Writers take the shared lock first and get a 404 after a merge. Timestamps are byte-equal in the DB tests.
- **Unlink.** Hard cascade with a server count. A failed unlink deletes nothing, and relinking stays empty.
- **Soft delete and restore.** Rows are kept, the API returns 404 while trashed, and restore returns the same ids. Purge cascades.
- **Export/import.** v1 and legacy files get no facts and keep the description verbatim. v2 recreates fresh ids with the original fields. Over-limit files are rejected, never truncated.
- **Spoilers and contexts.** Character details assembler, spoiler model and book section are not in the diff. Reveal state stays above the tabs.
- **Generated client.** All 22 generated files still on disk (13 modified, 9 new; 28 were deleted) share one mtime window, 2026-10-17 14:48:18 to 14:48:40.
