# Frontend — читацькі цілі

Реалізація клієнтської частини фічі. Рішення — у [`README.md`](./README.md), контракти —
у [`backend-spec.md`](./backend-spec.md).

## Межі

- Починати **після** `pnpm gen:api` з готовим бекендом — інакше typecheck впаде.
- Нова фіча-скиба `apps/web/src/features/reading-goals/**` (`api/`, `components/`, `model/`,
  барель `index.ts`). Сторінка списку імпортує з неї один блок і більше нічого про цілі не знає.
- Не чіпати `apps/api/**` і `packages/shared/**`.
- Тексти — тільки через `next-intl`, обидві локалі одночасно (скіл `add-i18n-key`).
- Форма — `react-hook-form` + `zod` + примітиви shadcn **напряму**, без обгорток `<Form>` / `<FormField>`.
- Семантичні токени, не сирі кольори. `src/components/ui/**` не редагувати.

## Поверхні

| Де                      | Що                                  |
| ----------------------- | ----------------------------------- |
| Правий бар `/lists/:id` | блок `Ціль для добірки` — два стани |
| Модалка звідти          | `Створити ціль для добірки`         |
| Сторінка `/goals/:id`   | деталі цілі                         |

Індексної сторінки `/goals` і пункту в навігації **немає**. Єдиний вхід у ціль — правий бар списку.
Дублювати `Створити ціль` у меню `•••` списку теж не треба: два входи в одну модалку породжують
питання «а це те саме?».

# 1. Блок «Ціль для добірки»

Перший блок правого бара сторінки списку. Джерело — `useListGoal(listId)`.

Це **єдиний блок бара, який не ховається за відсутності даних** — порожній стан із кнопкою є
частиною сценарію.

## 1.1 Стан без цілі (`204` → `data === null`)

```
Ціль для добірки
Перетворіть цю тематичну добірку на читацький виклик.
[ Створити ціль ]
```

Клік **відкриває модалку**. Ніякого створення «одним кліком зі значеннями за замовчуванням».

Кнопка `disabled`, коли в списку немає жодної книги, з підказкою `Спочатку додайте книги до списку`.

## 1.2 Стан з активною ціллю

```
Ціль для добірки
Прочитати 8 книг до 30 листопада
5 із 8 виконано
[███████░░░]  63%
Залишилося 3 книги
[ Переглянути ціль ]
```

- Заголовок — `name`, якщо він заданий; інакше згенерований рядок `Прочитати {targetCount} книг до {deadline}`.
- Прогрес-бар: `aria-valuenow` передавати **явно** — вендорений `ui/progress` його не прокидає.
- `Залишилося N книг` — ICU-плюрал, ховається при `remainingCount === 0`.
- Дата — через `date-fns` з локаллю користувача, без ручного форматування.
- `Переглянути ціль` → `/goals/{id}`.
- Кнопки `Створити ціль` у цьому стані **немає** (одна неархівована ціль на список).

## 1.3 Стан `completed`

```
Ціль для добірки
🎉 Ціль виконана
8 із 8 · завершено 12 листопада
[ Переглянути ціль ]  [ Створити нову ціль ]
```

`Створити нову ціль` відкриває ту саму модалку — сервер сам архівує попередню, окремої дії
`Архівувати` в барі не потрібно.

## 1.4 Стан `expired`

```
Ціль для добірки
Дедлайн минув
5 із 8 · прострочено на 4 дні
[ Переглянути ціль ]  [ Створити нову ціль ]
```

Тон нейтральний. Ніяких «ви не впорались» — це особиста бібліотека, а не спортзал.
`daysLeft` тут від'ємний; форматувати як `Math.abs`.

## 1.5 Стан `archived`

Блок показує стан без цілі (§1.1) — архівована ціль у барі не живе, вона доступна лише за прямим
посиланням.

# 2. Модалка створення

```
Створити ціль для добірки

Джерело книг: «Книги на осінь» · 20 книг

Назва цілі (необов'язково)
[ Прочитати книги зі списку «Книги на осінь» ]

Прочитати книг *
[ 5 ]           У списку 20 книг

До дати *
[ 30.11.2026 ]

Ціль рахується лише за книгами з цього списку, прочитаними після її створення.

              [ Скасувати ]  [ Створити ціль ]
```

## Правила полів

**`Назва цілі`** — необов'язкове. Плейсхолдер (не значення!) — `Прочитати книги зі списку «{name}»`.
Порожнє поле шлеться як відсутнє, і бекенд віддає `name: null`; підпис у блоці тоді генерується
з цифр. Максимум 120 символів.

**`Прочитати книг`** — обов'язкове, ціле.

- мінімум `1`, максимум — кількість книг у списку;
- **значення за замовчуванням не дорівнює всій добірці.** Ставити `min(5, bookCount)` — користувач
  сам обирає реалістичну кількість, а підставлена «вся добірка» перетворює вибір на формальність;
- допоміжний текст `У списку {n} книг`;
- нуль, від'ємне й завелике — блокують сабміт із помилкою біля поля.

**`До дати`** — обов'язкове, строго пізніше за сьогодні.

- без валідного дедлайну кнопка `Створити ціль` заблокована;
- використати наявний `book-date-field.tsx` як взірець, не вигадувати новий пікер.

Помилки валідації — **біля відповідного поля**, не загальним банером зверху.

## Після успіху

1. закрити модалку;
2. success-toast `Ціль створено`;
3. інвалідувати `goalKeys.forList(listId)` — блок бара оновиться **без перезавантаження сторінки**;
4. фокус повертається на кнопку, що відкривала модалку.

## Помилки

- `409` (уже є активна ціль) — toast `Для цього списку вже є активна ціль` + інвалідація запиту,
  щоб блок одразу показав реальний стан. Це буває, коли ціль створили в іншій вкладці.
- `400` з `path` — підсвітити відповідне поле.
- решта — загальний toast `Щось пішло не так`, модалка лишається відкритою з даними.

# 3. Сторінка `/goals/:id`

Маршрут: `apps/web/src/app/[locale]/(app)/goals/[id]/page.tsx` + `generateMetadata`.
Серверний компонент рендерить тільки оболонку; дані тягне клієнтська фіча-компонента — як усюди.

```
← До списку «Книги на осінь»

Прочитати 8 книг зі списку «Книги на осінь»
до 30 листопада 2026 · залишилося 12 днів        [бейдж статусу]

[████████████░░░░░░]  5 із 8 · 63%
Залишилося 3 книги

Зараховані книги (5)
[обкладинка] Назва — Автор — дочитано 3 листопада
...

[ Редагувати ціль ]  [ Архівувати ]  [ Видалити ]
```

- Бейдж статусу: `Активна` / `Виконана` / `Прострочена` / `Заархівована` — кольори через семантичні
  токени (`success`, `warning`, `muted`), не сирі.
- `Зараховані книги` — з `countedBooks`, порядок `finishedAt ASC`, рядок клікабельний → деталі книги.
  Порожній масив → `Ще жодної книги не зараховано` + пояснення, що рахуються лише книги, дочитані
  після створення цілі.
- `Редагувати` — та сама модалка в режимі редагування (`name`, `targetCount`, `deadline`); для
  архівованої цілі кнопки немає.
- `Архівувати` — без підтвердження, з toast і дією `Скасувати`? Ні: скасування архівації сервером
  не передбачене. Показати `AlertDialog` із поясненням, що ціль зникне з бара.
- `Видалити` — `AlertDialog` із підтвердженням, після успіху `router.push('/lists/{listId}')`.
- Хлібна крихта «До списку» веде на список-джерело; для цілі без списку (майбутнє) — на `/lists`.
- `404` → той самий патерн, що в `list-details.tsx` (іконка, текст, кнопка повернення).

## Мобільна версія

Одна колонка. Прогрес-блок і зараховані книги — послідовно. Дії — у нижньому sticky-рядку або в
меню `•••` у шапці; не розкидати три кнопки по всій ширині екрана.

# 4. Стан і кеш

```ts
const GOALS_ROOT = "/api/goals";

export const goalKeys = {
  detail: (goalId: string) => [GOALS_ROOT, "detail", goalId] as const,
  forList: (listId: string) => [GOALS_ROOT, "for-list", listId] as const,
  root: [GOALS_ROOT] as const,
};
```

| Дія                                                    | Інвалідувати                           |
| ------------------------------------------------------ | -------------------------------------- |
| створити ціль                                          | `forList(listId)`                      |
| редагувати ціль                                        | `detail(goalId)`, `forList(listId)`    |
| архівувати                                             | `detail(goalId)`, `forList(listId)`    |
| видалити                                               | `forList(listId)`, редирект            |
| змінити статус книги на «Прочитано» зі сторінки списку | `forList(listId)` — прогрес міг зрости |

Остання строка важлива: користувач позначає книгу прочитаною просто на сторінці списку, і блок цілі
має оновитися того ж моменту. Це єдина точка зчеплення цілей із рештою сторінки.

**Жодних оптимістичних оновлень.** Прогрес цілі — похідне значення від стану книг; вгадувати його
на клієнті означає дублювати серверний домен, і при першому ж розходженні користувач побачить
цифру, якої не існує.

форматування, не `toLocaleDateString` уроздріб.

# 7. Тести

`frontend-test-engineer`, Vitest + RTL, мок на межі `fetch`.

- Блок без цілі показує кнопку створення; з активною ціллю — прогрес і `Переглянути ціль`, і
  **не показує** `Створити ціль`.
- `completed` і `expired` показують `Створити нову ціль`.
- Кнопка створення `disabled` при `bookCount === 0`.
- Форма: сабміт заблокований без дедлайну; дедлайн у минулому дає помилку біля поля; `targetCount`
  більший за кількість книг дає помилку біля поля; значення за замовчуванням **не** дорівнює
  кількості книг у списку.
- Порожня назва не шлеться як порожній рядок.
- Успіх закриває модалку й показує toast; `409` лишає модалку і показує конфліктний toast.
- Сторінка цілі: порожній `countedBooks` показує пояснення; `404` показує стан «не знайдено».
- Прогрес-бар має `aria-valuenow`.
