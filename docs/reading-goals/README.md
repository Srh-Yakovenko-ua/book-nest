# Читацькі цілі — карта фічі

Виділено з `docs/booknest-list-details-spec.md` (розділи «Створення цілі читання на основі списку»
і «Ціль для добірки»). Це **окрема фіча й окремий реліз**: вона єдина в усьому обсязі сторінки
деталей списку вимагає зміни схеми БД, і вона не блокує решту сторінки.

| Документ                                 | Про що                                              |
| ---------------------------------------- | --------------------------------------------------- |
| [`backend-spec.md`](./backend-spec.md)   | модель, міграція, контракти, обчислення прогресу    |
| [`frontend-spec.md`](./frontend-spec.md) | блок у правому барі, модалка, сторінка `/goals/:id` |

## Що це таке

Ціль — окрема сутність, яка **посилається** на кастомний список як на джерело книг. Список
лишається тематичною добіркою: у нього не додаються ані дедлайн, ані цільова кількість.

> Прочитати 8 книг зі списку «Книги на осінь» до 30 листопада 2026 року.

## Прийняті рішення

| Питання                 | Рішення                                                                                                                                                                                                            |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Скоуп                   | **Тільки цілі за списком.** Загальних цілей («прочитати 50 книг за рік») у першій реалізації немає. У моделі `listId` усе одно nullable — щоб додати їх пізніше без міграції.                                      |
| Розділ у застосунку     | **Тільки сторінка деталей `/goals/:id`.** Індексної сторінки `/goals` і пункту в навігації немає. Єдиний вхід у ціль — правий бар сторінки списку.                                                                 |
| Нагадування про дедлайн | **Поза обсягом.** Прапорець `readingGoalReminders` у профілі лишається неактивним. Жодних BullMQ-джоб і cron.                                                                                                      |
| Статус цілі             | **Обчислюється на льоту** при читанні (`active` / `completed` / `expired` / `archived`). У БД зберігається лише `archivedAt`.                                                                                      |
| Що рахується прогресом  | Книги списку, **прочитані після створення цілі** (`finishedAt >= день створення цілі`). Уже прочитані до створення не зараховуються — інакше ціль може виявитися виконаною в момент створення, і це вже не виклик. |
| Скільки цілей на список | Одна **неархівована**. Створення нової автоматично архівує попередню, якщо та вже виконана або прострочена. Якщо попередня ще активна — `409`.                                                                     |
| Дата виконання          | Не зберігається — це `finishedAt` тієї книги, яка закрила ціль. Обчислюється разом із прогресом.                                                                                                                   |

## Відома поведінка, яку свідомо приймаємо

`finishedAt` скидається доменом при будь-якому переході зі статусу `Прочитано` — зокрема при
переході в `Перечитую` (`apps/api/src/modules/books/domain/reading-status-transition.ts:82`).
Тому якщо користувач почне перечитувати книгу, яка вже зарахована в ціль, **прогрес зменшиться**.

Це прийнятно для першої реалізації: сценарій рідкісний (перечитати книгу, дочитану в межах
поточної цілі, до її дедлайну). Якщо він виявиться болючим — лікується таблицею-знімком
`reading_goal_books`, куди книга потрапляє в момент зарахування; це вимагає хука в сервіс читання
і робиться окремо.
