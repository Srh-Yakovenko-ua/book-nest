# Quick filter counts follow the query

The number on a quick filter chip is the size of the result the reader gets by clicking it: the count applies the current search and advanced filters and ignores the quick filter that is selected right now, so picking one chip never zeroes the others. Before this, pages disagreed. Library, favorites, loans and dedications showed library-wide totals that did not move with search, delivery hid the numbers during a search, notes, tags, genres and quotes followed the query, and publishers showed none. A static total reads as a promise the click then breaks ("Reading 12" opens two books), and hiding the numbers removes them exactly when a search makes them useful. The cost is a count query per page that takes the list's own filter parameters, kept separate from the library-wide summary that feeds sidebars and stat cards, which stays unfiltered on purpose. A chip at zero stays enabled and shows a muted 0, because a chip disabled on a count that is still refetching can block a valid click and a disabled item breaks arrow-key movement in the group. While counts refetch, the previous numbers stay on screen. "All" carries a count like every other chip. Every page draws the number through `ChipGroup`'s `count` option, never a hand-built label.
